## 2. 架构速览

```
cmd/mtls-gw       装配层: 组装 auth(认证)+ configmgr(配置/路由中枢)+ proxy(转发)
internal/proxy    数据面: 路由匹配(Match)+ 反向代理(转发); 零依赖其他核心包(只依赖 pathutil)
internal/auth     认证: Authorize(CA验证+IP预检+DB查表→角色); 只依赖 db
internal/db       SQLite 证书存储(purpose 逗号分隔单列, 代码拆成数组)
internal/configmgr 配置中枢: cfg + router + 校验 + 落盘(热重载: admin 改→rebuild→新 router)
internal/relay    客户端中继: 隧道 + 证书源 + /info 发现
internal/relayweb 客户端 WebUI
```

三种入口(概念不同, 见 §4 耦合分析):
- **业务路由**(gatewayHandler): mappings 声明, 转发到后端, roles 授权(any=任意已登记证书 / null=匿名 / 具体角色=交集)
- **/info**(infoHandler): 内置端点, 服务发现引导
- **/admin/*** (adminHandler): 内置端点, 管理操作(签发/吊销/改配置), admin_role 证书

## 3. 最近改动(2026-08-21, commit b7fa3b5..c93993c)

1. **null 内置类型**: 服务 roles 写 `null` = 该路由匿名可访问(不需要证书)。TLS 层改 `VerifyClientCertIfGiven`(有证书验证/坏证书拒绝/无证书放行到应用层), 应用层把关: 非 null 路由无证书 → 403。`null` 是保留字(AddRole 拒绝声明, NewRouter 豁免校验)。
2. **info+admin 合并端口**: `info_listen` 与 `admin_listen` 相同 → 一个端口, `/info`(匿名引导)+ `/admin/*`(admin 证书)路径区分(mux 用 `/admin/` 前缀匹配)。
3. **/info 匿名引导**: 无证书 → 200 + CA 证书(客户端过滤系统证书源用)+ 空服务列表; 有证书认证通过 → CA + 按角色过滤的服务列表; **有证书但吊销/未登记 → 403**(不泄漏)。
4. **客户端自动过滤**: relay 配 server_ca 后异步匿名调 /info 拿 CA → 过滤系统证书源(winSource.SetIssuerFilter, issuer 精确匹配 CA 主题); server_ca 未配降级不过滤。
5. **连接设置 WebUI 卡片**: server_addr/admin_addr/server_ca/listen_host/lang 可编辑 + 保存即热重载(PUT /api/settings → UpdateSettings → reloadTunnels)。
6. **便携式配置**: relay 默认配置路径 = exe 同目录 config.json(不再 ~/.mtls-relay); 首次启动自动生成默认配置(EnsureDefaultConfig)。
7. **loadCerts 空响应防御**: /api/certs 返回 null 时前端不崩((certs || []) + 提示)。
8. **公开仓库清理真实 TS IP**: git filter-repo 重写全部历史, 真实 IP → RFC 6598 占位符(100.64.0.1/.2)。**注意: 历史已重写, commit hash 全部变了, 外部 clone 需重新同步。**

## 4. 耦合分析(用户关注点, 待办核心)

**现状**: 业务路由(mappings+services+roles)与管理端点(/info、/admin)是**两套概念**:
- 业务: 配置声明入口, roles 授权, handler 转发
- /info + /admin: 内置硬编码端点, 特殊授权逻辑, handler 为网关自身操作

**用户倾向**: 统一授权模型 —— /info、/admin 也纳入"角色 → 能否访问"的统一机制:
- `/info` 角色可配置(默认 `["null"]` 匿名引导, 可改 `["dsh"]` 只让特定证书看)
- `/admin` 强制 admin_role
- 授权走同一个 Authorize 流程

**代价**: 需改 infoHandler(去硬编码"无证书→CA", 改按配置角色)、配置加字段、更新测试。**用户认可代价大, 决定后续由另一个 agent 做**。

**包层面耦合已评估**: proxy 零依赖认证/配置(单向干净), auth 只依赖 db。当前耦合点 = main.go 装配层 + /info 读 Router(单向投影)。
